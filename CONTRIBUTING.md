# Contributing

Contributions to **ReplayLinkerRP** are welcome. Keep changes focused on the
extension, validate what you change, and document compatibility changes clearly.

Please read [`CODE_OF_CONDUCT.md`](CODE_OF_CONDUCT.md) before participating.
Security vulnerabilities must be reported privately through
[`SECURITY.md`](SECURITY.md), not through public issues or discussions.

## Before you start

For substantial UI, compatibility, or release-process changes, open a GitHub
issue or discussion first when practical. Small fixes and documentation
corrections can be submitted directly as a focused pull request.

New to the project? Look for issues labelled
[`good first issue`](https://github.com/indpriyanshuraj/ReplayLinkerRP/labels/good%20first%20issue)
or
[`help wanted`](https://github.com/indpriyanshuraj/ReplayLinkerRP/labels/help%20wanted).
You do not need to know Minecraft JSON UI to contribute — documentation,
testing, and compatibility reports are all valuable.

## Repository structure

- [`src/`](src/) — source files for the Déesse extension resource pack.
- [`docs/`](docs/) — architecture, compatibility, FAQ, troubleshooting, UI
  reference, and development setup documentation.
- [`scripts/build_release.sh`](scripts/build_release.sh) — reproducible
  `.mcpack` builder (supports `--check` for validation-only).
- [`.github/`](.github/) — CI workflows, issue templates, PR template,
  labeler, and dependabot.
- [`CHANGELOG.md`](CHANGELOG.md) — release history following Keep a Changelog.
- [`README.md`](README.md) — user-facing documentation.
- [`LICENSE`](LICENSE) / [`NOTICE`](NOTICE) — license and attribution.

For a detailed annotation of every UI JSON file, see
[`docs/ui-reference.md`](docs/ui-reference.md).

## Source changes

The working pack lives under [`src/`](src/). Do not commit generated
`.mcpack` files.

When modifying the pack:

- Preserve Déesse's UI integration conventions unless the change requires
  otherwise.
- Keep the extension lightweight; replay functionality belongs to the native
  mods.
- Keep compatibility claims accurate for Déesse, Minecraft, LeviLaunchroid,
  LeviLamina, and the supported replay implementation.
- Include attribution and licensing information for any third-party material.
- Update documentation when changing behavior or compatibility.

## Validation

Required local tools: `bash`, `jq`, `zip`, `unzip`.

```bash
# Full build (produces .mcpack in dist/)
./scripts/build_release.sh v1.0.0

# Validate only — no archive produced (used by CI)
./scripts/build_release.sh --check v1.0.0

# Check for whitespace issues
git diff --check
```

Test user-facing changes in an actual supported environment and record the
Minecraft, Déesse, loader/launcher, and replay-mod versions used.

### Optional: pre-commit hooks

A [`.pre-commit-config.yaml`](.pre-commit-config.yaml) is included for local
quality checks (JSON validation, markdown lint, shellcheck, whitespace):

```bash
pip install pre-commit
pre-commit install
```

### CI

Every pull request runs `.github/workflows/ci.yml`, which validates all JSON
files, checks the manifest version against SemVer, runs the build in `--check`
mode, and lints markdown. Your PR must pass all checks before merging.

## Documentation

Update the relevant docs when you change something:

- [`docs/architecture.md`](docs/architecture.md) — integration flow changes.
- [`docs/ui-reference.md`](docs/ui-reference.md) — UI files added/removed/restructured.
- [`docs/compatibility.md`](docs/compatibility.md) — supported versions change.
- [`docs/faq.md`](docs/faq.md) — a question comes up frequently.
- [`docs/troubleshooting.md`](docs/troubleshooting.md) — a new common issue is identified.
- [`README.md`](README.md) — installation, requirements, or user-facing changes.
- [`CHANGELOG.md`](CHANGELOG.md) — release-relevant changes (Keep a Changelog format).

## Pull requests

A good PR explains what changed and why, links a relevant issue when one
exists, describes testing performed (with version info), and mentions
compatibility impact. Do not include generated release archives unless
specifically needed for review.

## Reporting problems

Use [GitHub Issues](https://github.com/indpriyanshuraj/ReplayLinkerRP/issues)
with the appropriate template (bug report, feature request, documentation
issue, or compatibility report). Use
[GitHub Discussions](https://github.com/indpriyanshuraj/ReplayLinkerRP/discussions)
for questions and broader ideas.

For security vulnerabilities, follow [`SECURITY.md`](SECURITY.md).
For conduct concerns, follow [`CODE_OF_CONDUCT.md`](CODE_OF_CONDUCT.md).

## Release process

Releases are generated by GitHub Actions from SemVer tags. The workflow builds
the pack from `src/`, minifies JSON, creates the compressed `.mcpack`, and
extracts release notes from `CHANGELOG.md`. Do not manually commit generated
release packages.
